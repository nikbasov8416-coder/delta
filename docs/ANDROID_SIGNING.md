# Постоянная подпись Android

Ключ создаёт и хранит **владелец**, не агент. Один и тот же ключ нужен для всех
следующих APK: смена ключа мешает обновлению установленного приложения.
Сохранить keystore и его пароли в надёжном резервном хранилище. GitHub Secrets
не заменяют собственную резервную копию: скачать оттуда исходные значения нельзя.

На своём ПК с JDK владелец запускает в личной папке **вне git**:

```powershell
keytool -genkeypair -v -keystore delta-upload.jks -storetype JKS -alias delta-upload -keyalg RSA -keysize 3072 -validity 10000
```

Команда интерактивно запросит пароли и сведения сертификата. Пароли не вставлять
в командную строку, переписку или документацию. Ключ в приложение не входит.
Если keytool не установлен, JDK на ПК устанавливает владелец.

В приватном репозитории: Settings → Secrets and variables → Actions →
New repository secret. Создать четыре секрета:

| Имя | Содержимое |
|---|---|
| DELTA_ANDROID_KEYSTORE_BASE64 | файл keystore, кодированный base64 одной строкой |
| DELTA_ANDROID_STORE_PASSWORD | пароль keystore |
| DELTA_ANDROID_KEY_ALIAS | выбранный alias сертификата |
| DELTA_ANDROID_KEY_PASSWORD | пароль ключа; если совпадает с паролем keystore — всё равно указать |

В PowerShell получить base64 сразу в буфер обмена, без вывода в терминал:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path .\delta-upload.jks))) | Set-Clipboard
```

Вставить в GitHub Secret, затем очистить буфер. Keystore, base64 и пароли не
коммитить и не отправлять в Telegram. Для CI другие секреты не нужны.

Workflow восстанавливает keystore только во временной папке runner с правами
600, собирает **release APK** и удаляет временный файл шагом `always()`.
Секреты передаются Gradle только через окружение. Отсутствующий секрет, пустой
или неверный base64, неверные пароли/alias приводят к ошибке сборки. Перехода
на debug-ключ нет. Даже локальная Android-сборка требует постоянную подпись.
Для PR из fork секреты недоступны — Android job завершится понятной ошибкой;
анализ и тесты секретов не требуют.

Для обновлений CI увеличивает Android versionCode по номеру запуска.
На телефоне удалить старую сборку этапа 1 с временной debug-подписью придётся
один раз **до ввода реальных данных**. Самостоятельно удалять приложение с
данными ради исправления обновления не следует. Следующие сборки одним ключом
можно устанавливать поверх предыдущих.
