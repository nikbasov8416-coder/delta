# Приватное зеркало и сборки — действия владельца

Codex ничего не публикует. На GitHub уходит только содержимое `finance-app/`.
Реальные данные, пароли, ключи подписи и весь остальной личный проект не отправлять.

## Создать репозиторий

1. Создать новый аккаунт GitHub, включить двухфакторный вход и сохранить recovery codes.
2. Создать репозиторий `delta`, выбрать **Private**. Не добавлять README, лицензию
   или `.gitignore`: первая загрузка должна попасть в пустой репозиторий.
3. Настроить SSH-доступ к новому аккаунту из терминала. Ключи и токены не помещать
   в проект и не присылать в Telegram. Если нужны новые файлы вне проекта,
   их создаёт сам владелец. Для APK добавить четыре секрета по `ANDROID_SIGNING.md`.
4. Убедиться, что Actions разрешены для репозитория. У приватных репозиториев
   есть лимиты минут и места; Windows runner расходует минуты быстрее Linux.
   Платные перерасходы по желанию отключить в Billing.

## Первый push только папки приложения

Команды ниже выполняет владелец в терминале сервера под root. Вместо
`ВАШ_ЛОГИН` указать новый аккаунт. Предполагается, что git/SSH для пользователя
`claude` уже настроены владельцем. Секреты в аргументы команд не вставлять.

Сначала проверить итог ревью и состав дерева (без изменения индекса):

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && git status --short -- finance-app && git ls-tree -r --name-only HEAD:finance-app'
```

В выводе не должно быть баз (`.db`, `.sqlite*`), экспортов, `.env`, keystore,
`key.properties`, SDK, кэшей или сборок. Незакоммиченные изменения не попадут
в split. После проверки и приёмки создать отдельную ветку под общим замком:

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && python/bin/python ops/lock.py git subtree split --prefix=finance-app --branch=delta-mirror'
```

Проверить, что корень полученного дерева — приложение, а не личный проект:

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && git ls-tree --name-only delta-mirror'
```

Должны быть `pubspec.yaml`, `lib`, `android`, `windows`, `.github` и документация.
Не должно быть `memory`, `mail`, `ops` и папки `finance-app` как внешней оболочки.
Отправить **только** эту ветку в main нового пустого приватного репозитория:

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && python/bin/python ops/lock.py git push git@github.com:ВАШ_ЛОГИН/delta.git delta-mirror:main'
```

Не выполнять `git push --all`, `--mirror`, `--tags` и не отправлять основную
ветку личного проекта. Полную историю subtree перед первой публикацией
можно проверить через `git log --stat delta-mirror`: split сохраняет историю
именно этой папки. На этапе 1 в ней только исходники и выдуманные тесты.

## Обновить зеркало после следующих этапов

После ревью и фиксации новых изменений повторить `subtree split` без создания
ветки. Он напечатает SHA коммита приложения:

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && python/bin/python ops/lock.py git subtree split --prefix=finance-app'
```

Подставить полученный SHA вместо `КОММИТ_ПРИЛОЖЕНИЯ` и проверить дерево:

```bash
sudo -u claude -H bash -c 'cd /home/claude/Claude && git ls-tree --name-only КОММИТ_ПРИЛОЖЕНИЯ'
sudo -u claude -H bash -c 'cd /home/claude/Claude && python/bin/python ops/lock.py git push git@github.com:ВАШ_ЛОГИН/delta.git КОММИТ_ПРИЛОЖЕНИЯ:main'
```

Если push отклонён, не применять `--force`: сначала выяснить причину расхождения.
На GitHub код зеркала вручную не менять, иначе появятся две линии истории.

## Скачать и проверить сборки

Вкладка Actions → «Проверка и сборки Delta» → успешный запуск → Artifacts:

- `Delta-android` — ZIP артефакта с подписанным `app-release.apk` внутри.
- `Delta-windows-x64` — ZIP артефакта с `Delta-windows-x64.zip` внутри;
  распаковать внутренний ZIP целиком, запускать `delta.exe` рядом с DLL и `data`.

Артефакты хранятся 7 дней. APK подписывается постоянным ключом из секретов
владельца. Подготовка — `ANDROID_SIGNING.md`; при отсутствии секретов сборка
завершается ошибкой. Временный debug-ключ не используется. Для установки
поверх прежней версии нужен тот же ключ; старую сборку этапа 1 с временным
ключом удалить до начала работы с реальными данными. Сам ключ агент не создаёт.

Windows-сборка x64 рассчитана на Windows 10+; возможна потребность в Microsoft
Visual C++ Runtime. Установку компонентов на ПК выполняет владелец.
Проверки analyze/test выполняются до сборок. Windows job дополнительно запускает
тест SQLCipher своей платформы. Первый реальный запуск Actions и установка на
устройства — после публикации владельцем; сервер Linux их не заменяет.
