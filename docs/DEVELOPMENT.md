# Разработка и проверки

Зафиксированы Flutter stable **3.50.0**, Dart **3.14.0** и `pubspec.lock`.
SDK на сервере: `/home/claude/Claude/tools/flutter`; системной установки нет.
Android SDK здесь не нужен: сервер выполняет анализ и тесты Linux.
Восстановление SDK и SHA256 — в основном проекте `ops/MIGRATION.md`.

Под пользователем claude из корня личного проекта:

```bash
finance-app/tool/flutterw pub get --enforce-lockfile
finance-app/tool/flutterw pub run build_runner build
finance-app/tool/flutterw analyze --no-pub --fatal-infos
finance-app/tool/flutterw test --no-pub --reporter expanded
python/bin/python finance-app/tool/dependency_inventory.py
```

`tool/flutterw` перенаправляет кэши/временные файлы внутрь проекта и подавляет
телеметрию CLI. Системные HOME и PATH не меняет. Использовать обёртку только
в основном проекте; в самостоятельном зеркале с установленным Flutter
выполнять обычные `flutter …` / `dart …` из корня приложения.

SQLCipher подключён build hook пакета sqlite3. При первом тесте/сборке он
скачивает нативную библиотеку нужной платформы с проверкой SHA256.
Тест неправильного ключа намеренно вызывает диагностические сообщения
SQLCipher о невозможности расшифровать страницу; это ожидаемый отказ.
В лог не выводятся ни ключ, ни содержимое базы. Тест создаёт только искусственный
файл в системной temp-папке runner; обёртка сервера задаёт TMPDIR внутри проекта.
Файл удаляется при завершении теста.

После изменения схемы перегенерировать `app_database.g.dart` и фиксировать
его вместе с исходниками: CI проверяет, что повторная генерация не меняет файл.
Не редактировать generated-код вручную. Форматирование:

```bash
dart format lib test
```

Все тесты используют только выдуманные значения. Пакеты для следующих этапов
добавлять отдельно с обновлением lockfile и `DEPENDENCIES.md`.
Реальные базы, экспорты, ключи, `.env`, `key.properties`, keystore и сборки
исключены `.gitignore`. На сервере только выдуманные тесты; на устройствах ядро
уже сохраняет зашифрованные слепки. Резервный экспорт и синхронизация пока отсутствуют.

Проверки CI:

- Linux: lockfile, drift generation, форматирование, analyze, все тесты Dart и проверки подготовки подписи Python.
- Android после проверок: `flutter build apk --release`, minSdk 26, постоянная подпись (секреты владельца).
- Windows x64 после проверок: тесты, `flutter build windows --release`,
  упаковка всего каталога Release в ZIP.

На сервере нельзя подтвердить Windows/Android-сборки без соответствующих
toolchain. Их первая фактическая проверка — Actions после публикации владельцем.

## Сообщения коммитов

Коммиты, затрагивающие `finance-app/`, уходят в приватное зеркало вместе с
сообщениями. Использовать нейтральные технические формулировки, без сумм,
названий банков, имён и иных личных сведений. Пример: «Delta: обновление ядра».
Постоянная подпись Android — по `ANDROID_SIGNING.md`; debug-fallback запрещён.


## Проверка этапа 2 на устройствах (после ревью)

1. Настроить постоянный ключ по `ANDROID_SIGNING.md`; установить подписанный APK.
   Старый временный APK этапа 1 удалить до начала работы с данными.
2. Задать PIN, проверить неверный PIN и задержку после пяти ошибок; перезапустить
   приложение во время задержки. Проверить вход после правильного PIN.
3. Создать выдуманное место с двумя валютами, добавить уровень ликвидности,
   создать слепок, ввести суммы с запятой и пробелами и семейную часть.
4. Проверить, что фиксация не разрешена без подтверждения строк/курса. Ввести
   ручной курс, зафиксировать; проверить все группировки итогов.
5. Исправить строку, курс и заметку зафиксированного слепка; проверить историю.
   Создать следующий слепок, проверить копирование и добавление валюты из него.
6. Перезапустить приложение и убедиться в сохранности выдуманных данных;
   установить следующий APK тем же ключом поверх предыдущего — данные сохранены.
7. Включить и проверить отпечаток на Android / Windows Hello на Windows.
   Короткий уход в фон скрывает экран, длительный требует входа заново.
8. На Android проверить запрет скриншота и превью, затем явное выключение
   в настройках. На Windows проверить ключевое хранилище и работу без Hello
   через PIN. Провести проверку на Windows 10+ x64 с нужным VC++ Runtime.

На Linux без устройства нельзя подтвердить Keystore/Credential Manager,
отпечаток/Hello, флаги Android, подпись и обновление APK. Тесты не подменяют
приёмку этих возможностей владельцем. При ошибке открытия база не стирается.
